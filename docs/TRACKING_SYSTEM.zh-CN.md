# 追踪系统

WRobot 使用状态机驱动的视觉追踪流程，参考云台相机和自主移动系统的分层设计。视觉置信度和机器人运动分离，弱检测或丢失检测不能直接驱动底盘。

## 流程

1. 用户启用追踪，并选择目标类别：Face、Animal 或 Ping-pong ball。
2. 用户在 Web UI 中框选目标区域。
3. MaixCam 确认框内检测到了用户选择的类别。
4. MaixCam 通过 UART 上报追踪状态、画面中心误差、尺寸误差、置信度、目标类别和目标框。
5. ESP32 通过统一 `MotionCommand` 接口执行平滑、限幅、命令超时和恢复逻辑。

当前版本禁用不支持的任意物体追踪。当框内检测不到用户选择的类别时，固件不会使用 NanoTrack 或 MixFormer 回退。

## 状态

- `IDLE`：追踪关闭，或等待新的选择。
- `ACQUIRING`：目标类别需要连续多帧稳定，机器人不移动。
- `LOCKED`：置信度和几何关系有效，允许云台、转向和距离控制。
- `COASTING`：短暂检测中断视为遮挡，底盘立即停止运动。
- `REACQUIRING`：检测器尝试在上一次目标区域附近重新捕获同类别目标，机器人不做盲目搜索转身。
- `LOST`：恢复超时，停止运动，摄像头回到待命角度。

## 安全规则

- 只有 `LOCKED` 观测可以触发正常底盘运动。
- UART 追踪更新超过 400 ms 丢失会触发恢复并停止前进。
- 重新捕获阶段不允许前后运动。
- 首次锁定前，失败检测保持在 `ACQUIRING`，不会让底盘旋转。
- 摄像头校正限速，避免俯仰动作累计。
- 当目标框中心或尺寸变化不合理时会拒绝该帧。
- 选中的目标必须持续匹配用户选择的语义类别。如果漂移到其他物体，MaixCam 应上报遮挡或重新捕获，而不是错误锁定。

## 默认调参位置

摄像头参数在 `maixcam-code/config.py`。底盘和云台参数在 `robot-code/src/motion/MotionCoreAdapter.cpp`。

实机调试应先架空轮子，验证静止获取，再依次验证左右移动、距离变化、短暂遮挡、长时间遮挡、UART 断连和模式取消。

## 协议

当前 UART 观测格式：

```text
TRK:LOCKED,DX:12,DY:-4,DZ:8,Q:935;
```

`Q` 是 0 到 1000 的置信度。兼容旧版 `DX/DY/DZ` 命令。

## 预测式载体控制

摄像头观测包含与分辨率无关的 `EX`、`EY`、`EZ` 误差。滤波后的目标速度可预测略超过一帧的目标方向，预测范围受目标框大小限制。自适应目标框平滑让快速移动响应更快，同时保持慢速目标稳定。

底盘转向使用独立的启动和释放阈值。方向需要连续多次一致，才允许受限转向启动或反向，避免延迟相机观测造成左右震荡。摄像头误差会转换成和 Web / Gamepad 控制一致的底盘 yaw 与前后极性。IMU yaw-rate 反馈会阻尼命令；停止的变化率快于加速；居中后残余追踪 yaw 积分会衰减。距离运动需要连续尺寸误差观测，并在初始距离基准稳定后启动。
