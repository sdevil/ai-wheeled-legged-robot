# 预测式追踪架构

WRobot 使用检测器主导的类别化追踪。底盘不会直接根据未验证的视觉框运动。

## 流程

1. 用户在 Web UI 选择目标类别。
2. 用户在实时视频上框选目标。
3. MaixCam 使用对应检测器确认框内目标：人脸、动物或乒乓球。
4. 固件对目标位置和速度做滤波，并在短暂视觉中断时做有限预测。
5. 连续丢失后，按目标类别进行局部或全局重新捕获。
6. ESP32 通过 UART 接收归一化方向误差、距离误差、置信度、状态和追踪 profile。
7. MotionCore 使用自己的限速 yaw、pitch、距离控制闭环。

## 追踪 Profile

- `1`：人脸，平滑跟随。
- `2`：动物，较快跟随。
- `3`：乒乓球，最快的安全追逐响应。

Profile `0` 只用于空闲或不支持目标，不应驱动机器人运动。

每种目标都会保留初次锁定时的距离。摄像头会在锁定后的前几帧稳定目标框高度，再启用距离运动。手动拉近或拉远会替换这个距离基准。

每个 `TRK` 帧都会带 `P:<profile>`。`COASTING` 状态下禁止前后运动。`REACQUIRING` 只允许在目标曾经进入 `LOCKED` 后出现。

## 乒乓球模型

内置 COCO 检测器可以回退使用 `sports ball` 类。可靠的小球追逐建议安装一类专用模型：

- `/root/models/wrobot_pingpong.mud`，用于 YOLO11
- `/root/models/wrobot_pingpong_yolov8.mud`，用于 YOLOv8

摄像头默认 640x480，并提供 320x240 低延迟和 160x120 远程操控配置。推理帧会按每个模型的输入尺寸转换和缩放；MJPEG 分辨率和模型 tensor 尺寸相互独立。

## 安全

- 没有确认帧时，预测不能触发前后运动。
- 置信度参与电机命令门控。
- yaw 和 drive 命令都有加速和减速限制。
- 目标丢失后，摄像头回到待命角度，机器人停止。
